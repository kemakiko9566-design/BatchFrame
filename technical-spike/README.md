# 手机端验证

运行 `npm install`，然后 `npm run dev`。选择平台和比例，添加 JPEG、PNG 或 WebP，选择白边、相纸或摄影师参考，再生成 JPEG。支持系统文件分享的浏览器在结果页提供分享面板入口，其余提供逐张下载与打开图片入口。

处理链路为原图 File → 缩略图预览 / 原图顺序渲染 → JPEG 文件 → 系统分享或逐张保存。两条渲染路径共用 `packages/core/layout.ts`。Canvas2D 支持原生图像解码后备路径，不依赖 OffscreenCanvas。

自动检查：`npm run build`，`node technical-spike/verify-layout.cjs`。几何检查覆盖相纸外形与成像区、原图完整适配、预览与输出一致性、留白及异常输入，不代替浏览器和手机测试。

人工验收：

1. 在 390 × 844、320px 宽屏幕检查横向溢出、相纸卡片、底部操作与弹层。
2. 导入横图、竖图、全景与带 EXIF 方向的 JPEG，确认完整保留、比例、方向及 JPEG 像素尺寸；测试透明 PNG 和 WebP。
3. 切换三种相纸、白边档位、自定义宽高、背景色以及平台外框；平台模拟不得出现在输出图片。
4. 检查返回保留照片、添加去重、移除、处理中取消、部分失败、重新生成。
5. 在 iPhone Safari 与 Android Chrome 检查文件分享能力、单张/批量保存、取消分享、逐张降级及返回页面。需要安全上下文；通过局域网普通 HTTP 打开的页面可能无法调用分享。
6. 连续生成 20 张 24MP 图片，记录内存与响应，不宣称未实测的性能或相册保存结果。

相纸的四边偏移近似，摄影师参考为单件尺寸推算，来源见界面详情。源图解码和所有结果文件均占用内存；顺序渲染不意味着内存恒定。输出限制为 40MP / 单边 16384px。
